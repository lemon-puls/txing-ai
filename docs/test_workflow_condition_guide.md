# 条件节点工作流测试指南

本文档说明如何测试智能研究助手工作流，该工作流包含了所有节点类型和条件分支功能。

## 工作流架构

```
                                    ┌─────────────┐
                                    │   开始节点   │
                                    └──────┬──────┘
                                           │
                                    ┌──────▼──────┐
                                    │  需求分析    │
                                    │   (LLM)     │
                                    └──────┬──────┘
                                           │
                                    ┌──────▼──────┐
                                    │  搜索信息    │
                                    │  (工具节点)  │
                                    └──────┬──────┘
                                           │
                                    ┌──────▼──────┐
                                    │ 搜索结果判断 │ ← 表达式判断
                                    │  (条件节点)  │
                                    └──────┬──────┘
                                           │
                          ┌────────────────┼────────────────┐
                          │ true                           │ false
                          ▼                                ▼
                   ┌─────────────┐                  ┌─────────────┐
                   │  内容生成    │                  │  错误提示    │
                   │   (LLM)     │                  │   (LLM)     │
                   └──────┬──────┘                  └──────┬──────┘
                          │                                │
                   ┌──────▼──────┐                  ┌──────▼──────┐
                   │  质量判断    │                  │  结束(错误)  │
                   │  (AI判断)   │                  └─────────────┘
                   └──────┬──────┘
                          │
            ┌─────────────┼─────────────┐
            │ true                    │ false
            ▼                         ▼
     ┌─────────────┐          ┌─────────────┐
     │  保存文档    │          │  优化提示    │
     │  (工具节点)  │          │   (LLM)     │
     └──────┬──────┘          └──────┬──────┘
            │                         │
     ┌──────▼──────┐                 │
     │    完成      │                 │
     └─────────────┘                 │
            ▲                         │
            └─────────────────────────┘
                   (循环重试)
```

## 节点说明

### 1. 开始节点 (start_1)
- **类型**: start
- **功能**: 接收用户输入

### 2. 需求分析 (llm_analyze)
- **类型**: llm
- **功能**: 分析用户输入，提取研究主题、关键词和方向
- **配置**:
  - 温度: 0.3 (低随机性)
  - 最大Token: 1024
  - 上下文: 关闭

### 3. 搜索信息 (tool_search)
- **类型**: tool
- **功能**: 使用 web_search_tool 搜索相关信息
- **配置**: 绑定 web_search_tool

### 4. 搜索结果判断 (condition_search)
- **类型**: condition
- **判断类型**: 表达式判断
- **表达式**: `{{output}} not_equals ''`
- **功能**: 判断搜索结果是否为空
  - **true**: 搜索成功，继续生成内容
  - **false**: 搜索失败，提示错误

### 5. 内容生成 (llm_generate)
- **类型**: llm
- **功能**: 根据搜索结果生成研究报告
- **配置**:
  - 温度: 0.7
  - 最大Token: 2048
  - 上下文: 开启 (记住历史对话)

### 6. 质量判断 (condition_quality)
- **类型**: condition
- **判断类型**: AI判断 (LLM)
- **提示词**: 评估内容质量是否达标
- **功能**: AI 自动判断生成内容的质量
  - **true**: 质量达标，保存文档
  - **false**: 质量不达标，重新生成

### 7. 保存文档 (tool_save)
- **类型**: tool
- **功能**: 使用 markdown_save_tool 保存生成的内容

### 8. 错误提示 (llm_error)
- **类型**: llm
- **功能**: 搜索失败时生成友好的错误提示

### 9. 优化提示 (llm_retry)
- **类型**: llm
- **功能**: 质量不达标时优化提示，重新生成内容

### 10. 结束节点
- **end_success**: 成功完成
- **end_error**: 错误结束

## 测试步骤

### 步骤 1: 导入测试工作流

```bash
# 连接数据库
mysql -u root -p txing_ai

# 执行 SQL 文件
source sql/test_workflow_condition.sql
```

### 步骤 2: 启动应用

```bash
# 启动后端服务
go run cmd/main.go
```

### 步骤 3: 配置模型

1. 访问 http://localhost:8080/dash
2. 登录后台
3. 进入 "渠道管理"，确保至少有一个 AI 渠道配置
4. 记下可用的模型名称（如 deepseek-chat）

### 步骤 4: 编辑工作流

1. 进入 "工作流管理"
2. 找到 "智能研究助手-测试工作流"
3. 点击 "设计流程" 进入编辑器
4. 为每个 LLM 节点选择模型：
   - 点击节点
   - 在右侧属性面板选择模型
   - 点击 "应用配置"
5. 保存工作流

### 步骤 5: 运行测试

1. 在工作流编辑器页面，点击顶部 **"运行测试"** 按钮
2. 输入测试内容，例如：
   ```
   请帮我研究一下人工智能在医疗领域的应用现状
   ```
3. 点击 **"开始运行"**
4. 观察执行流程：
   - 需求分析节点提取关键词
   - 搜索工具执行搜索
   - 条件判断节点评估搜索结果
   - 内容生成节点创建报告
   - 质量判断节点评估内容
   - 保存节点保存文档

## 测试场景

### 场景 1: 正常流程（搜索成功，质量达标）

**输入**:
```
请研究一下 2024 年大语言模型的最新发展
```

**预期流程**:
1. 需求分析提取关键词
2. 搜索成功
3. 搜索结果判断 → true
4. 生成研究报告
5. 质量判断 → true
6. 保存文档
7. 完成

### 场景 2: 搜索失败

**模拟方法**: 断开网络或使用无效搜索词

**输入**:
```
请研究一下 xxxxxxxx 这个不存在的内容
```

**预期流程**:
1. 需求分析提取关键词
2. 搜索失败或返回空结果
3. 搜索结果判断 → false
4. 错误提示
5. 结束（错误）

### 场景 3: 质量不达标（循环重试）

**预期流程**:
1. 需求分析提取关键词
2. 搜索成功
3. 搜索结果判断 → true
4. 生成研究报告
5. 质量判断 → false
6. 优化提示
7. 重新生成
8. 再次质量判断
9. 重复直到达标或达到重试上限

## 调试技巧

### 查看日志

```bash
# 查看后端日志，关注条件判断结果
# 日志中会显示：
# - "Executing Condition node" - 条件节点执行
# - "Condition result" - 条件判断结果
# - "Condition branch selected" - 分支选择结果
```

### 常见问题

1. **模型未选择**
   - 错误信息: "创建模型失败"
   - 解决: 在节点属性面板中选择模型

2. **搜索失败**
   - 错误信息: 搜索结果为空
   - 解决: 检查网络连接，或更换搜索词

3. **循环重试过多**
   - 原因: AI 判断质量一直不达标
   - 解决: 降低质量判断标准，或优化生成提示词
